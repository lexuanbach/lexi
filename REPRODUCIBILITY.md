# Reproducibility

This file gives the environment, the exact commands with measured runtimes, what is
deterministic, and the known limits. `README.md` has the short version.

## Environment

| Item | Tested value |
| :-- | :-- |
| OS | macOS 26.5, arm64 |
| Hardware | Apple M5 Max laptop. Every experiment uses one core and under 1 GB of memory. |
| Python | 3.13.5 (fresh virtual environment) and 3.14.6. Python 3.11 or newer is required by numpy 2.4. |
| Packages | `requirements.txt`: numpy 2.4.6, matplotlib 3.10.9 and their pinned dependencies. `lexi/requirements.txt` gives the looser minimum versions of the code base. |
| Optional tools | `pdfinfo` (poppler) for the page-count check of `scripts/verify.sh`. |
| Not needed | GPU, cluster, network access, credentials, API keys, LaTeX. |

Linux and Windows were not tested. The code is plain Python and numpy with no
platform-specific calls. numpy 2.5.3 with matplotlib 3.11.2 was also tested: every result
file is identical and Fig. 2 differs from the paper only in anti-aliasing.

## Setup

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export PYTHONDONTWRITEBYTECODE=1
```

The scripts in `scripts/` set `PYTHONDONTWRITEBYTECODE=1` themselves. The export matters
only when you call `python3 lexi/...` directly. `scripts/verify.sh` removes bytecode caches
before it checks the manifest.

## Determinism

The workload of seed `s` uses `numpy.random.default_rng(s)`, execution noise uses
`default_rng(1000 + s)`, the curated menu uses seed 0 and the random menu uses `100 + s`.
The main comparison uses seeds 0 to 14, the weight sweep 0 to 5, the other sweeps 0 to 7.
The bootstrap intervals and paired tests use fixed seeds as well. Wall-clock timings are
the only non-deterministic values: `scalability` in `core_results.json`, `rx5_scaling` in
`robustness_results.json` and the `runtime_s` fields. The papers present them as
machine-dependent. `scripts/check-claims.py` prints them as INFO, and
`scripts/compare-results.py` reports them as TIMING without failing.

## Verifying outputs

- `scripts/check-claims.py` first runs `lexi/check_results.py` (97 claims), then checks 214
  numbers of the two papers (117 camera-ready, 97 extended) against the result files with
  a tolerance of half a unit of the last printed digit. `CLAIM_MATRIX.md` lists them.
- `scripts/compare-results.py RELEASED_DIR REGENERATED_DIR` compares result files key by
  key. `run-full.sh` and `run-extended.sh` call it automatically.
- `EXPECTED_RESULTS.md` shows the final lines each command prints on success.

## Known limits and differences

1. **Simulation only.** Every number comes from the purpose-built simulator. The papers
   make no testbed claim, and nothing here measures orchestration overhead, migration
   cost or network jitter.
2. **Stability hold (disclosed in the current camera-ready).** `controller.thresholded_lex_select`
   keeps the previous placement when it survives the three bands and applies the cost
   tie-break only otherwise. Def. 2 of the camera-ready states the cost tie-break, and
   Sect. 5 now reports that Lex-LP, the same rule without this hold, matches Lexi on all
   24,000 main-run decisions (`core_results.json`, `lexlp_agreement` and
   `e1_satisfaction.lexlp_vs_strict_max_gap`). For the strict rule the hold changes 0 of
   24,000 decisions in the main run, 0 of 12,800 on the random menu and 24 of 24,000 in the
   real-trace run, all 24 before the evaluation window (`decision_checks.json`,
   `hysteresis_effect`). The extended version describes the hold in Alg. 1 and Sect. 5.3.
3. **`improve_lexi.json`, row `Lexi-thr(ship)`.** This row (5.12% SLO, PII 0.03) was
   produced with the first default slack, `DEFAULT_ETA = (0.04, 0, 0.08)`, which put a
   slack of 0.04 on the SLO hinge. The current `DEFAULT_ETA` is `(0, 0, 0.08)`, and a rerun
   gives 1.425% SLO and PII 0.054, the same as row `Lexi-thr-fixed`. Running
   `CausalContinuum` with `eta=(0.04, 0, 0.08)` reproduces 5.1167% and 0.03 exactly. No
   number in either paper uses this file.
4. **`robustness_experiments.py` run as a script.** Its `main()` (called by
   `lexi/run_robustness.sh`) runs RX1 to RX7 in one pass and completes. An earlier version of
   its summary print read keys that `rx2_doubly_robust` does not return and stopped with a
   `KeyError` after writing the JSON. The print is fixed and no computed value changed.
   The one-pass file still differs from the committed `robustness_results.json`: it runs the
   RX3 sweeps on five seeds where the committed file uses two (weight sweep) and three
   (baseline sweeps), which gives 16.4% of weightings meeting the target against 14.6% in
   the committed file (0% dominate Lexi in both). It also keeps the intervals and paired
   tests that the shard merge of RX1, RX2 and RX4 does not store, and its RX1, RX2 and RX4
   means match the committed ones up to the last rounded digit. RX6 and RX7 are identical.
   The one-pass run took 567 s. `scripts/run-extended.sh` follows `run_incremental.py`
   with the committed seed counts and reproduces the committed file.
5. **Corrected in the current papers.** Earlier builds of the papers had four small
   wording errors that the artifact exposed. The current PDFs fix them and
   `scripts/check-claims.py` checks the corrected values: the model of the worked
   decision is fitted on steps 0 to 903 (both papers), the extended version's Sect. 4.3
   now prints the predicted carbon 1.683, 1.190, 0.968 and 0.784 g and calls the
   objectives of the chosen placement noise-free, Sect. 8.1 states a per-node phase, and
   the Table 9 caption gives the seed counts (15 unless marked, 2 to 5 for the marked
   rows).
6. **Timing claims.** "Under 0.1 ms per decision" and the extended-version slope depend on
   the CPU. A rerun on the test machine, with other jobs running, measured 0.088 to 0.104 ms
   for 8 to 128 candidates and 0.092 ms at 32 and 48 candidates.
7. **Real traces.** The carbon and load traces are fixed excerpts. The papers do not claim
   anything about other days or regions.
